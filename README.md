# AeroPulse

Учёт статистической отчётности гражданской авиации: формы **12-ГА** (авиакомпании) и **15-ГА** (аэропорты).

Программа принимает присланные отчёты в XLSX и XML, складывает их в локальную базу и показывает сводные и подробные таблицы с отбором по предприятию, периоду, показателям и видам маршрутов. Готовый отчёт выгружается в XLSX.

Пользователь у программы один: разграничения доступа нет и не предполагается — вход нужен, чтобы отчётность не открывалась случайному человеку за тем же компьютером.

## Требования

* Python 3.12 или новее (CI проверяет 3.12 и 3.14)
* Windows, macOS или Linux. Собранный дистрибутив рассчитан на Windows; на остальных системах программа запускается из исходников.

## Установка

**Windows — установщиком.** Скачайте `AeroPulse-Setup-<версия>.exe` из [релизов](../../releases) и запустите. Программа ставится в профиль пользователя, права администратора не нужны; Windows 10 или новее. Обновление — запуск установщика новой версии поверх старой: данные при этом не трогаются.

Первым запуском Windows покажет предупреждение SmartScreen — установщик не подписан сертификатом. «Подробнее» → «Выполнить в любом случае».

**Из исходников** — на любой системе:

```bash
pip install -r requirements.txt
python main.py
```

Точка входа — только `main.py` в корне. Запуск отдельных модулей `forms/` не поддерживается.

**Первый запуск.** База создаётся сама, и программа сразу просит завести администратора: логин, почту и пароль не короче 8 символов. Учётной записи по умолчанию нет — пары «admin/123» в коде не существует.

Если базу подготовить не удалось (нет прав на запись, повреждённый файл, неудачная миграция), программа скажет об этом окном и назовёт путь журнала, а не закроется молча.

## Где что лежит

Программа и её данные лежат раздельно. Каталог данных — корень проекта при запуске из исходников и `%LOCALAPPDATA%\AeroPulse` у установленной программы:

| Что | Где |
|---|---|
| База | `db/database.db` |
| Резервные копии | `db/backups/` — последние 10, снимаются перед импортом, правкой и удалением |
| Журнал работы | `aeropulse.log` — до 2 МБ, три предыдущих файла |

Отдельного журнала загрузок в файле нет: он ведётся в самой базе, таблица `import_log`.

Рядом с exe не создаётся ничего: тот каталог принадлежит установщику — обновление перезаписывает его целиком, удаление сносит. Удаление программы данные не трогает: их туда не клал установщик, а переустановка — обычный способ починить сломанную установку. База, оставшаяся там от версий до установщика, переезжает в каталог данных при первом запуске новой версии, вместе с копиями и журналом. Не удалось перенести — программа не запускается и говорит почему: начать работу с пустой базой, пока прежняя лежит на месте, выглядит как потеря всей отчётности.

## Импорт отчётов

Принимаются `.xlsx`, `.xls` и `.xml`; регистр расширения значения не имеет.

**Форму определяет содержимое файла, а не выбор в диалоге.** Если выбрана авиакомпания, а файл оказался бланком 15-ГА, импорт отклоняется — данные не попадут в чужую форму.

**Предприятие можно не выбирать.** В списке предприятий первым пунктом стоит «— предприятие из файла —»: отчёт называет своё предприятие сам — 12-ГА в титуле XML, 15-ГА в шапке бланка, — и брать название из диалога незачем. Так грузится годовой комплект сразу на несколько авиакомпаний: одна папка, один заход.

Название в отчёте уставное («Акционерное общество "Авиакомпания "АЛРОСА"»), в справочнике короткое («АО Авиакомпания АЛРОСА») — сравниваются они по приведённому виду, без оглядки на кавычки, регистр и организационно-правовую форму словами. Ненайденное в справочнике предприятие заводится при импорте: авиакомпания — с кодом из титула отчёта, аэропорт — с населённым пунктом по своему же названию и служебным кодом. Всё заведённое перечисляется в отчёте об импорте, а настоящий код проставляется потом в «Справочниках».

**Сводный бланк предприятия принимается целиком.** ФКП «Аэропорты Севера» присылает не отчёт на аэропорт, а одну книгу: сводный блок предприятия и блок на каждый из его аэропортов. Такой файл раскладывается по аэропортам сам, а сами аэропорты помечаются как входящие в предприятие — от этого зависит «Итого» в сводке.

**Отчётный период обязателен.** В книге он читается с листа «Титул», ячейка D13; в XML — из атрибутов отчёта, а если их нет, из хвоста имени файла: `0615106_12_12_2269_2025_1.xml` — это январь 2025 года. Если прочитать не удалось, программа спрашивает месяц и год, а не подставляет их за пользователя. Файл без указанного периода не импортируется.

**Импорт заменяет период целиком.** Строки, исчезнувшие из исправленного отчёта, удаляются из базы — поэтому перед загрузкой пакета снимается копия базы, а сама загрузка попадает в журнал.

Пакет из нескольких файлов обрабатывается в фоне: виден прогресс по файлам, загрузку можно прервать. Отмена срабатывает между файлами — начатый файл дописывается до конца, чтобы не оставить период переписанным наполовину.

## Что показывают вкладки

**Аэропорты (15-ГА).** Вкладка открывается сводкой по всем аэропортам — тем же листом, что и в годовой сводке 15-ГА: строка на аэропорт, колонки по периодам, в каждом одиннадцать граф бланка. Периоды идут как в сводке — три месяца, квартал, снова три месяца, квартал, полугодие и так до «12 месяцев»; квартал и нарастающий итог показываются только тогда, когда все их месяцы попали в выбранный период.

Аэропорт, входящий в предприятие, стоит с отступом под его строкой. «Итого» складывает только предприятия: сводный бланк предприятия и есть сумма его аэропортов, и сложение всех строк подряд посчитало бы их дважды.

Кнопка «Аэропорты» отбирает строки — так же, как отбираются авиакомпании на соседней вкладке. Выбран ровно один аэропорт — вместо сводки показывается сам бланк 15-ГА со всеми его строками.

## Правка и удаление записей

Переключатель «Подробный (правка и удаление)» показывает не свод, а сами записи — по строке на значение бланка.

Запись правится двойным щелчком по строке, кнопкой «Редактировать выбранное» или тем же пунктом в меню по правой кнопке. Менять можно значение, месяц и год; предприятие, показатель и вид маршрута — то, чем запись является, и в диалоге они только показаны. Если за новый период такая запись уже есть, правка отклоняется: ключ отчётной строки — показатель, предприятие, месяц и год.

Перед правкой и удалением снимается копия базы, а само изменение попадает в журнал (таблица `import_log`): прежнего значения после записи не остаётся больше нигде. Если копию снять не удалось, программа спрашивает, продолжать ли, — и по умолчанию не продолжает.

## Выгрузка

Кнопка «Экспорт в XLSX» выгружает то, что на экране. В книгу уходят числа числами (а не текстом), русская запись разрядов остаётся форматом ячейки, а перед таблицей идёт шапка: форма, предприятие, период, счётчики, момент выгрузки и пользователь. Лист называется по форме.

Итоги уходят формулами, а не готовыми числами: «ИТОГО» складывает графы бланка, «Свод» — авиакомпании месяца, квартал сводки 15-ГА — свои месяцы, строка «Итого» — предприятия. Поправив в Excel одну колонку, итог видно сразу.

Формулой становятся и те ячейки, которые бланк объявляет суммой, но приложение не считает, а получает из отчёта: графы «Всего (гр.4+гр.5)» и строки 03, 07, 08 формы 15-ГА, тоннокилометраж 12-ГА. Такая формула пишется только после сверки — если она даёт ровно то же число, что на экране. Не сошлось (отчёт с расхождением, слагаемое вне отбора, «Х» неприменимой графы) — в ячейке остаётся число.

Формулы записываются без готового результата: Excel и LibreOffice считают их при открытии, а вот `pandas` и `openpyxl` увидят такие ячейки пустыми, пока книгу не открыли и не сохранили.

## Схема базы

SQLite. Схема приводится к актуальной версии миграциями Alembic при **каждом** запуске — править её вручную не нужно и нельзя.

| Таблица | Что хранит |
|---|---|
| `users` | учётные записи; пароль — хеш scrypt, не открытый текст |
| `airlines`, `airports`, `airport_localities` | справочники предприятий и населённых пунктов; аэропорт может ссылаться на предприятие, в состав которого входит |
| `routes`, `shipping` | вид маршрута и регулярность; рейс — пара «авиакомпания + маршрут» |
| `indicators` | показатели форм: код, название, единица измерения |
| `airlineInd`, `airportInd` | сами отчётные значения по форме 12-ГА и 15-ГА |
| `import_log` | журнал загрузок, замен и удалений |

Значения отчётности хранятся текстом и читаются как `Decimal`: у SQLite нет десятичного типа, и через `float` число из бланка возвращалось бы приближением.

Предприятия не удаляются, а выводятся из работы: отчётность за прошлые годы остаётся, но в списках выбора предприятие больше не предлагается.

## Сборка дистрибутива

Собирается на Windows, в два шага:

```bash
pip install -r requirements.txt -r requirements-build.txt
pyinstaller aeropulse.spec
```

```bash
iscc installer\AeroPulse.iss
```

Первый шаг даёт `dist/AeroPulse/` — саму программу; своих данных она туда не пишет, поэтому каталог установки может быть доступен только на чтение. Второй упаковывает это в `dist/AeroPulse-Setup-<версия>.exe` и требует [Inno Setup](https://jrsoftware.org/isinfo.php) 6.3 или новее.

Версия задаётся один раз — в `pyproject.toml`. Оттуда её берёт спека и вписывает в свойства exe, а установщик читает уже из собранного файла: разойтись им негде.

Оба шага выполняет CI на каждый push в `main` — готовый установщик лежит в артефактах сборки. Тег вида `v1.2.3` дополнительно выкладывает его в релиз.

Установщик не подписан: сертификат стоит денег, а без него Windows встречает каждого нового пользователя окном SmartScreen. Это единственное, что отделяет сборку от полностью «обычной» программы.

## Разработка

```bash
python -m unittest discover -s tests -t .
python -m ruff check .
python -m mypy
```

Тесты слоя Qt идут без экрана — на Windows это работает как есть, на macOS и Linux нужен offscreen:

```bash
QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -t .
```

Все три выполняются в CI на каждый push и pull request — на 3.12 и 3.14, вместе с подсчётом покрытия (`coverage run -m unittest discover -s tests -t .`, сейчас 79%).

Новая ревизия схемы:

```bash
alembic revision --autogenerate -m "что изменилось"
```

Есть тест, который сверяет модель с линией миграций, — разойтись им не даст.

Разбор состояния кодовой базы и список известных проблем — в [ISSUES.md](ISSUES.md).

## Лицензия

Лицензия не выбрана. Права сохраняются за автором: репозиторий открыт для чтения, но разрешения использовать, изменять или распространять код он не даёт.
